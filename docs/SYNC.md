# GitHub 与本地双向同步

IDEA 与 Codex 打开同一个 Git 工作目录。IDEA 保存文件后，Codex 立即读到本地修改；GitHub 的变化通过 Git 提交同步。自动同步会把符合范围并通过检查的本地修改公开推送到当前分支，请只在这个开源项目目录内启用。

## 常用命令

```sh
# 同步一次：检查本地改动、获取远端提交、必要时合并并推送
npm run sync

# 查看当前分支、脱敏后的远端地址、待处理文件数和暂停原因
npm run sync:status

# 在当前终端持续运行；Ctrl+C 停止
npm run sync:watch

# 修复暂停原因后恢复；运行中的服务会在下一个轮询周期处理
npm run sync:resume

# 安装当前用户登录后自动运行的同步服务，并立即启动
npm run sync:install

# 停止并取消登录自动同步，保留源码、提交和本地日志
npm run sync:uninstall
```

安装软件、下载源码、执行 `npm ci` 或打开 IDEA 都不会自动安装同步服务。只有明确执行 `sync:install` 才启用后台服务。请先按开发文档完成依赖安装，并确认 `npm run check` 通过。自动同步需要 **Git 2.38+**，以使用 `git merge-tree --write-tree` 在不修改工作目录的情况下预检合并冲突；可用 `git --version` 检查。

## 同步行为

- 每 2 秒检测本地变化，连续 10 秒没有新修改后开始检查；远端获取通常每 30 秒一次，同一时刻只允许一个同步进程。
- 每次发布前执行 `npm run check`。检查过程中源文件又发生变化时，等待下一轮重新检查。脚本不会自动安装依赖或修改 Git 身份、凭据。
- 本地修改通过检查后提交。远端领先且本地没有新提交时快进更新；双方都有提交时，先用 `git merge-tree --write-tree` 检测冲突，不修改工作目录。无冲突才创建合并提交，重新检查后推送。
- 冲突、检查失败或敏感内容会暂停同步，保留现有文件和双方提交。不会强制推送，也不会执行 `reset`、`clean`、自动变基或覆盖冲突。
- 网络或认证暂时失败时保留改动，按 30 秒、60 秒、120 秒等间隔重试，最长 5 分钟。不会把一次断网视为永久暂停。
- 仅同步当前本地分支到 `origin` 上的同名分支。切换分支后按新分支处理；分离 HEAD 或未完成的手动 Git 操作需要先处理。

Git 同步有提交、检查与网络延迟，不是逐键镜像。IDEA 和 Codex 的本地文件变化立即共享；远端变化会在同步完成后出现在 IDEA 中。

## 发布范围与敏感内容

默认只暂存 `src/`、`native/`、`scripts/`、`tests/`、`docs/`、`.github/`、`.run/`、`assets/` 中的源文件，以及根目录的 README、许可证、包清单/锁文件和标准工程配置。生成目录、可执行文件、账号文件、`.env`、证书和无关笔记不会自动加入提交。

暂存内容和所有即将推送的本地提交都会扫描常见私钥与访问令牌格式。即使后续提交删除了秘密，旧提交中仍保留的秘密也会阻止推送。日志只报告文件和问题类别，不输出匹配的秘密内容。扫描是附加保护，公开提交前仍应检查 `git diff --cached`。

检测到问题后，在 IDEA 的 Git 窗口查看改动与提交。确认处理完毕，再执行：

```sh
npm run check
npm run sync:resume
```

如果暂停原因是历史提交中的秘密，请先撤销相关凭据，并手动整理尚未发布的提交；脚本不会擅自改写历史。

## 后台服务与本地状态

macOS 使用当前用户的 LaunchAgent；Windows 使用当前用户、非管理员权限的计划任务。服务绑定安装时的项目目录和 Node 路径，移动项目或升级后删除了原 Node 路径时，应卸载后重新安装服务。

后台服务会在 Git 元数据目录保存 Node、npm 和绝对工具目录的 PATH，以便登录环境中仍能运行检查与 Git 凭据助手。不会复制整个终端环境或保存访问令牌。请先使用 Git/IDEA 完成正常登录；如果网络必须使用代理，请在当前仓库的 Git 配置中设置 `http.proxy`，不要只依赖当前终端的 `HTTP_PROXY`。本地 Git 配置不会进入公开提交。

运行状态、进程锁、npm 路径和日志保存在 Git 自身的 `quota-sync` 元数据目录中：普通仓库通常是 `.git/quota-sync/`，worktree 使用 Git 返回的对应元数据位置。这些文件不会被 Git 提交。

- `state.json`：暂停状态、最近结果和网络重试时间。
- `watch.log`：脱敏后的同步事件；macOS 另有 `stdout.log`、`stderr.log`。
- `lock.json`：当前同步进程。活跃进程持锁时，第二个实例不会启动。

若断电恰好发生在创建锁期间，可能留下 `lock.claim`。先关闭所有同步进程并确认没有后台任务运行，再手动检查该文件；脚本不会猜测并删除可能属于活跃进程的锁。

## 开发验证

```sh
node --test tests/sync/*.test.mjs
```

测试只使用临时目录中的本地 bare Git 仓库，覆盖双向更新、无冲突合并、冲突暂停、令牌拦截、检查失败恢复和检查中继续编辑。测试也实际执行小型 `npm run check`；生产同步没有跳过检查的环境开关。
